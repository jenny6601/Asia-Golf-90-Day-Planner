# System 51 hindcast pilot execution notes

The pilot script and manual GitHub Actions workflow use the exact request generated by the user's CDS download form:

- Dataset: `seasonal-original-single-levels`
- ECMWF System: `51`
- Initialization: `2016-01-01`
- Lead times: `408, 414, 420, 426` hours
- Variables: 10m u/v wind, 2m temperature, total precipitation
- Area: `[27, 127, 25, 129]` (north, west, south, east)
- Format: GRIB

## Before running

1. Confirm that the dataset Terms of Use have been accepted on the CDS dataset page.
2. In GitHub repository Settings → Secrets and variables → Actions, add a repository secret named `CDSAPI_KEY` containing the CDS personal access token. Never commit the token or paste it into chat.
3. Open Actions → **Retrieve SEAS5.1 System 51 hindcast pilot** → Run workflow, selecting branch `feature/ec46-seas5-api-audit-v1`.

The workflow writes the secret only to the runner's private `~/.cdsapirc` with restrictive file permissions. It does not print the credential. The downloaded GRIB and a manifest (request, byte size, SHA-256, retrieval time) are retained as a 30-day workflow artifact.

## Scope and limitations

This is one small retrieval test, not a forecast verification result. The CDS form request is preserved without adding undocumented request keys. After retrieval, inspect GRIB message metadata (parameter, units, step type, start/end step, member, valid time, and grid) to establish the actual temporal semantics. In particular, do not assume total precipitation is a 6-hour interval accumulation merely because lead times are spaced six hours apart.

No production application files are changed, no deployment is triggered, and the workflow does not merge this branch.
