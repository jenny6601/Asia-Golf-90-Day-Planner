# Phase 13 — C3S Okinawa sample retrieval

## Objective
Retrieve one reproducible, small sample from the C3S CDS daily/subdaily single-level seasonal dataset before writing an adapter.

## Verified dataset contract
- Dataset short name: `seasonal-original-single-levels`.
- Variable: `total_precipitation`.
- Native output: 24-hour accumulated precipitation, units metres of water equivalent.
- Grid: global regular latitude/longitude, 1° × 1°.
- Forecasts: 2017 to present; hindcasts: 1993–2016.
- Temporal output: daily and subdaily fields; seasonal forecast length is at least six calendar months but differs by originating centre.
- Update schedule shown by CDS: ECMWF on the 6th at 12 UTC; other centres on the 10th at 12 UTC.
- Dataset format: GRIB; experimental NetCDF4 is selectable in the CDS request form.

Source: https://cds.climate.copernicus.eu/datasets/seasonal-original-single-levels

## User-side CDS setup required
1. Sign in or register at https://cds.climate.copernicus.eu/.
2. Open the dataset page above and accept its Terms of Use in the download form.
3. In the form, choose at least two non-ECMWF originating centres (for example UK Met Office and JMA, if the requested initialization/system is available). Do not assume a system identifier; select only the values actually offered by the live form.
4. Select `Total precipitation`, the latest common initialization date available for the selected centres, and lead-time hours covering at least 90 days (2,160 hours). The available lead-time options may differ by centre.
5. Select a small Okinawa bounding box: North 27.0, South 25.5, West 127.0, East 128.5. This is a sample extraction region, not golf-course-resolution data.
6. Prefer NetCDF4 only if the current form explicitly offers it for this dataset; otherwise retrieve GRIB.
7. Use “Show API request code” to obtain the exact current request payload. The live form is authoritative for allowed systems, dates, lead-time values and format.

## Security
- Configure the CDS API token in the user's own GitHub repository as an Actions secret named `CDS_API_KEY` (or another agreed secret name).
- Never paste the token into chat, commit it to Git, add it to browser JavaScript, or place it in a public issue.
- The CDS API setup guide currently instructs users to use the API URL `https://cds.climate.copernicus.eu/api` and the personal access token, and to install `cdsapi>=0.7.7`.
- Dataset terms must be accepted manually before API retrieval.

## Sample validation requirements
- Preserve centre, system, initialization, lead time, valid date, member identity, units and retrieval timestamp.
- Convert metres to millimetres only in a documented normalization step.
- Verify whether each field is a 24-hour accumulation and how the forecast lead-time convention defines its valid date.
- Confirm at least two distinct non-ECMWF centres are present in the downloaded sample.
- Compare daily ensemble distributions with hindcasts from the exact same centre and system. Never pair a forecast with another system's hindcast.
- Report coverage by centre, lead day and Okinawa grid cell; missing data must remain missing.
- Do not produce calibrated rain probabilities or trip rankings until hindcast skill is evaluated for Okinawa and the target season.

## Exit criteria
- [ ] User has accepted the dataset terms and obtained a CDS token.
- [ ] Exact API request payload generated by the live CDS form is available.
- [ ] Sample download completes for at least two distinct non-ECMWF centres.
- [ ] NetCDF/GRIB metadata and precipitation units are verified.
- [ ] At least one matched hindcast sample for each selected centre/system is available.
- [ ] Reproducible parser and data-quality tests are written.

Until these criteria pass, no live CDS adapter is added and the existing recommendation engine remains unchanged.
